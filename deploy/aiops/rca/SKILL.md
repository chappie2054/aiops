# 自动根因分析

当用户要求故障诊断，或定时巡检指令到达时，先运行 `node /workspace/aiops-rca/scan.mjs`。默认只检查配置的业务命名空间；不要扩大范围或安装工具。命令直接在标准输出返回完整证据 JSON，无需写文件、审批或提权。读取这份输出后再回答。

若 `status=healthy`，只报告扫描时间、命名空间与扫描数量，不编造故障。若发现异常，对每个异常按以下格式输出：

1. 异常对象及开始时间；
2. **已确认事实**：引用扫描结果中的事件时间、事件信息、容器状态和日志片段；
3. **疑似根因**：区分确定性分类和模型推断，说明置信程度；
4. 缺失证据与待验证假设；
5. 恢复建议、影响和验证步骤。不要把 `CrashLoopBackOff`、`Pending` 或“副本不可用”本身称为根因。

如果同一 Deployment 和 Pod 同时异常，合并为一项故障，不重复计数。遇到镜像拉取失败先看事件中的仓库错误；遇到 OOMKilled 引用容器终止状态；日志为空时明确写“未取得应用日志”。自动任务只读诊断，不执行修复、回滚或创建集群资源。用户明确要求处理后再讨论具体变更。
